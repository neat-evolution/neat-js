# Profiling `@neat-evolution/demo`

This document serves as the "bible" for profiling the `@neat-evolution/demo` application and its underlying packages.

## Goals

The primary goal is to identify code paths that are consuming excessive CPU cycles during evolution.
Key areas for optimization:
1. **Genome Reproduction:** Mutation, crossover, and genome structure management.
2. **Network Activation:** The performance of the neural networks generated by NEAT, CPPN, HyperNEAT, etc.
3. **Fitness Evaluation:** The overhead of the environment and evaluation strategy.

## Profiling Tools

We use standard Node.js and Vitest tools for profiling and benchmarking.

### Node.js Profiler

We use the built-in Node.js profiler to generate CPU profiles.

```bash
yarn workspace @neat-evolution/demo profile
```

This runs `scripts/profile.js` which uses the `demo` function with specific `evolutionOptions` to keep the run short and focused. It generates a `profile.json` file.

### Vitest Benchmarking

We use Vitest's benchmark tools for micro-benchmarking specific functions and operations.

```bash
yarn workspace @neat-evolution/demo bench
```

## Customizing the Profiling Run

The `demo` function in `src/demo.ts` accepts `DemoOptions` to control the profiling run:

```typescript
export interface DemoOptions {
  method?: Methods
  evolutionOptions?: Partial<EvolutionOptions<any, any>>
  datasetOptions?: Partial<DatasetOptions>
}
```

Example usage in a benchmark or profiling script:

```typescript
await demo(createReproducer, createEvaluator, createExecutor, {
  evolutionOptions: {
    iterations: 1,
    secondsLimit: 2,
  }
})
```

## Infrastructure Requirements

- **Evaluator Factory:** Requires `EvaluatorFactoryOptions` which must include `createExecutor`.
- **Executor Factory:** Essential for phenotype execution during evaluation.

## How to Analyze Reports

### CPU Profiles (`profile.json`)

The `profile` script generates a processed JSON report. You can use tools like `speedscope` or Chrome DevTools to visualize this data. Look for high "self time" in functions within the `@neat-evolution` namespace.

### Benchmarks

Benchmarks provide timing information for specific tasks. Use them to track the impact of optimizations.

## Common Fixes

- **Caching:** Identify repeated calculations and cache results.
- **In-place Operations:** Reduce object allocation during critical paths (e.g., network activation).
- **Algorithm Optimization:** Streamline complex logic in genome reproduction.
